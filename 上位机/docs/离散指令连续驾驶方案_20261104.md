# 离散指令、连续驾驶与通信容错方案

日期：2026-11-04。状态：已完成双端实施、相关软件验证和固件构建；未连接、烧录或运动实车。实施细节与产物见第10节。

## 1. 目标与范围

方向键或未来脑控输出离散事件，上位机保存驾驶意图，MCU 连续执行速度闭环。输入结束不清除运动状态；不同方向轴可以叠加，同轴相反指令相互抵消。线速度和角速度独立调整。

本方案采用直接的线速度/角速度控制，不采用曲率控制。保持角速度时提高线速度，弯道半径会变大。稳定速度指车体中心线速度，转弯时左右轮速本来就不同。

同时放宽连续驾驶的通信抖动检查。真正断连、指令被拒绝、设备故障和 STOP 仍结束本次驾驶；短时延迟不再立即停车。

## 2. 方向状态与输入规则

保存两个状态：前后轴 `drive ∈ {-1,0,+1}`，转向轴 `turn ∈ {-1,0,+1}`。正值分别为前进、左转。

对任意一个轴，收到方向事件 `d ∈ {-1,+1}` 时：

| 原状态 | 新状态 |
|---|---|
| 中立 0 | d |
| 与 d 相同 | 保持 d |
| 与 d 相反 | 0 |

因此，同向重复不叠加速度；反向一次抵消，反向第二次才进入另一方向。按下事件生效，释放只解除按键去重，不改变驾驶状态。屏蔽操作系统长按自动重复。

| 输入 | 作用 |
|---|---|
| ↑ / ↓ | 更新前后轴，互相抵消 |
| ← / → | 更新转向轴，互相抵消 |
| W / S | 线速度幅值增加 / 减小一级 |
| A / D | 角速度幅值减小 / 增加一级 |
| 空格 / STOP | 清除两轴、取消后续目标、立即停止并失能 |
| 没有新指令 | 保持两轴和幅值 |

不增加“↑ 自动回正”：前进左转状态下再按 ↑ 仍为前进左转，按 → 才回正。这样两轴含义始终独立。

九种组合为静止、前进、后退、原地左右转、前进左右弯、后退左右弯。静止/中立只是目标为零，设备可以保持本次使能；STOP 会失能。使能与恢复连接均从双轴中立开始，不恢复历史运动状态。

按键同时按下时由同一输入批次归并：同轴正反同时出现视为该轴中立，不同轴正常组合；分开收到的指令按上述状态表顺序处理。归并应在输入适配层完成，不能依赖键盘事件到达顺序决定最终方向。

### 2.1 幅值与目标生成

建议初始参数如下，已作为软件默认值，实车效果待验证：

| 项目 | 默认 | 单次步长 | 范围 |
|---|---|---|---|
| 线速度幅值 V | 0.10m/s | 0.05m/s | 0～实际连续 CAPS 线速度上限 |
| 角速度幅值 W | 0.30rad/s | 0.10rad/s | 0～实际连续 CAPS 角速度上限 |

幅值达到上限后不再累积隐藏数值，按一次减小即可离开上限。幅值为零不会翻转方向；再次加速可沿保留的方向运动。对应轴处于中立时，调整幅值只改变预设。

目标：`v = drive × V`；`omega = turn × W`。倒车时对 omega 再取反，沿用当前“后退＋左＝向左后方行驶”的路径语义；无前后分量时左/右仍表示原地逆/顺时针旋转。

V/W 独立限幅，不再使用共同倍率，不因调整转向而自动缩小线速度。MCU 原有差速余量与 PWM 限幅继续生效；界面显示限幅状态。优先保持车体线速度意味着高速度下转弯能力可能下降，不能同时保证任意速度和任意角速度都达到。

### 2.2 一条完整操作序列

`↑ → ← → D → → → ↓`

依次为：前进 → 前进左转 → 增强左转 → 抵消左转、继续前进 → 抵消前进、正常减速至零。中间每次松键均保持状态。

### 2.3 未来脑控接口

键盘和脑控适配器都生成带来源、序号、生成时间的指令事件，交给同一状态更新入口；不能由界面或识别线程直接写串口。

- 一个确认的选择生成一个事件。重复传输同一事件不能重复调速；去重缓存必须有界。
- 新一轮确认可以再次产生相同指令，例如连续两次“加速”。不能仅按类别相同而永久抑制。
- “无新选择”保持状态；“识别进程停止/连接失效”使用独立健康状态，不用识别类别代替心跳。
- 第一版实现统一事件入口与键盘适配；真实脑控识别、置信阈值和决策窗口在接入具体识别器时确定。

## 3. 连续执行与调度

MCU 以 100Hz 运行角速度外环和轮速内环，以 20Hz 提供连续反馈。脑控选择和上位机目标发送各自计时。当前发送周期见[连续控制使用说明](连续控制使用说明.md)。

方向或幅值变化后保存最新意图。到达下一次发送时间且上一条目标已确认后，发送当前的绝对 v/omega。等待期间只保留最新意图。

STOP 独立优先处理。

MCU 在 10ms 周期内平滑逼近目标，初版沿用线加速度 0.5m/s²、角加速度 2rad/s²；普通减速与回正采用相同变化率。不得在普通方向事件后重新初始化 PI 或目标前置滤波。

必须修改当前“任一目标分量为零立即清该分量”的行为：普通归零也经过变化率限制；实际执行目标的两个分量都到零后再清控制器。STOP、故障和期限到期仍绕过平滑立即停车。例如从 0.30rad/s 回正，参考目标按现有变化率约 150ms 到零；实际车辆响应需另行测量。

## 4. 实施前突然停止的检查结果（历史快照）

以下是形成方案时从源码核对的实施前状态，新默认模式现已按第5节更新；原操控保留原Host检查：

| 条件 | 当前行为/阈值 | 位置 |
|---|---|---|
| 连续 ARM/TARGET 未确认 | 200ms 后 STOP | continuous_models.py、continuous_service.py |
| 连续遥测未更新 | 200ms 后 STOP | ContinuousService.poll |
| 基础 STATE 未更新 | 500ms 失去新鲜状态 | controller.project_state_fresh、ContinuousService.poll |
| MCU RX/TX 丢弃计数变化 | 任一次变化即 STOP | ContinuousService.poll |
| 主机通信积压标志 | 出现即 STOP | controller.pump_io、ContinuousService.poll |
| MCU 连续目标有效期 | 1000ms，到期停车 | continuous_control.h/c、project_link.c |
| MCU 陀螺数据过期 | 超过 60ms 停车 | continuous_control.c |
| 蓝牙后台在途发送 | 超过 3s 终止后台并报告连接错误 | bluetooth_worker.py |

上位机通信检查触发 STOP 不等于蓝牙链路断开。控制器只有收到传输 error/closed 或后台结束等事件才把连接状态置为未连接。当前停止提示把多种原因合并，容易混淆两者。

本轮没有找到与用户所述突然断连对应的录制证据，因此这些是已确认的触发条件，不是对某一次实车故障的定因。

## 5. 新默认模式的通信容错配置（已实施）

仅对新的连续驾驶模式应用以下设置，参数读写、有限实验和首次使能的检查不整体放宽。

| 项目 | 现值 | 方案值 | 执行规则 |
|---|---|---|---|
| 连续 ARM/TARGET ACK 等待 | 200ms | 600ms | 200ms 起显示延迟；600ms 仍未确认则停止，不重发 |
| 运行中连续遥测新鲜度 | 200ms | 1000ms | 超过 300ms 提示抖动；到 1000ms 停止 |
| 运行中基础 STATE 新鲜度 | 500ms | 1000ms | 超过 500ms 提示延迟；到 1000ms 停止 |
| 首次使能的基础 STATE | 500ms | 保持 500ms | 使用真实能力、新鲜状态和校准检查 |
| MCU 目标有效期、ARM 空闲期 | 1000ms | 2000ms | Host/MCU/CAPS 同步；不因收到重复旧帧延长 |
| MCU RX/TX 丢弃计数增加 | 任一次即停 | 记录并告警 | 不单独停车，继续由 ACK、新鲜度及设备实际状态判断 |
| 短时主机处理积压 | 标志出现即停 | 500ms 持续宽限 | 容量未溢出时先排空；连续 500ms 未恢复则停 |
| 真实缓冲区溢出/解析链失去可信状态 | 停止 | 保持停止 | 不与单次处理预算耗尽混为一类 |
| 蓝牙发送超时 | 3s | 保持 3s | 已明显大于 ACK 窗口，暂不继续放大 |
| MCU 陀螺有效期 | 60ms | 保持 60ms | 这是闭环反馈有效性，不是蓝牙延迟 |

上述参数旨在容忍约 200～500ms 的短时无线/调度抖动，不承诺任意 1s 中断仍持续运动：有在途目标时，600ms 的 ACK 截止可能先触发停止。

2000ms 的设备期限意味着主机完全失去控制、STOP 无法到达时，设备最多维持到最后一个已接受目标的绝对期限；这比原方案最多多约 1s。正常检测到故障时仍立即发送 STOP，不能等待设备期限才处理。

### 5.1 所有相关检查必须一致修改

不能只改 poll 中的一个数字：`running`、`prepare(continuous_target)` 和发送时钟估计目前也依赖全局 500ms STATE 新鲜度。增加连续运行专用的新鲜度判断，检查连接、会话、状态序号和 1000ms 年龄；首次 ARM 和其他服务继续使用现有判断。

连续遥测的年龄以接收线程记录的原始接收时间计算，不能以主线程刚刚解析它的时间重新计时；也不能由重复/倒序帧刷新新鲜度。基础 STATE 与连续 STATE 分别检查，只要任一超时就结束驾驶。

ACK 迟到但未过 600ms：确认后继续发送最新意图；过期后退休请求、清状态并停止。之后迟到的 ACK 或恢复的遥测不能重新使能。会话变更、MCU 报告失能/退出 mode 6、参数 revision 变化、本地禁止、IMU 无效、明确拒绝和真实断连均直接结束驾驶。

丢弃计数单次增加只告警，不修改其真实值；缺 ACK 仍在 600ms 停，遥测失新仍在 1000ms 停。这样只取消“计数变化本身必然停车”，不把丢失的命令当作执行成功。

主机积压必须区分“处理预算耗尽，需要下轮继续”和“实际容量溢出”。宽限期间暂缓新的普通目标，优先排空接收、处理 ACK；STOP 可用。单在途与绝对期限继续约束设备，不能通过不断续发掩盖处理链阻塞。

## 6. 协议与固件兼容

方向叠加和 WASD 属于 Host；普通归零平滑和 2000ms 期限属于 MCU，完整方案需要更新双端。

建议以连续控制扩展版本 2 显式区分新行为，保持现有命令编号和载荷布局：

- CAPS version=2，flags=7：原算法/滤波就绪位加“普通零目标平滑过渡”能力位，lease_ms=2000。
- TARGET version=2；其余字段仍为 revision、绝对 deadline、v、omega。
- CONTINUOUS_STATE 结构保持；requested 与 executed 分别展示意图和实际过渡参考。
- 新 Host 只有确认实际 v2 CAPS 后才能使能本方案；旧 v1 固件显示“需更新连续驾驶固件”，不冒充已支持。
- 新固件拒绝不匹配的 TARGET 版本；旧 Host 无法通过新 CAPS 校验，需要双端配套升级。升级不改已有有限实验的协议和期限。
- deadline 按设备时钟和实际传输时间折算，保留时钟量化余量。旧 session、旧 seq、过期目标均不能续期。

最终协议文档需记录版本、flags 和回绕比较规则；不能只在 Host 放宽到 2s，而 MCU 仍按 1s 停车。

## 7. 界面与停止诊断

连续页显示两条独立状态轴、组合状态、V/W 设置值、当前请求、MCU 执行参考、实际反馈和限幅情况。方向高亮代表锁存状态，不代表物理键是否按住；WASD 高亮只表示输入事件。

通信状态分开显示：

- 正常：蓝牙已连接，连续驾驶中。
- 抖动：仍连接，显示 ACK 等待时间、STATE/连续遥测年龄、丢弃增量。
- 控制已停止但连接仍在：显示具体触发条件、测量值和阈值。
- 连接已断开：显示传输层原始错误或关闭原因。

记录每次停止的独立诊断：来源、原因码、最近请求序号/年龄、两类遥测年龄、队列年龄/容量状态、丢弃计数增量、MCU stop_reason、会话和模式。最近原因保留在页面，不被后续一般状态覆盖；写入有界本地事件日志，未开启完整录制时也能查到原因。

失焦、切页、最小化、关闭、手动断开沿用现有 STOP。未来脑控运行入口再使用独立的输入源健康规则，不在本次方案中擅自取消桌面失焦停止。

## 8. 实施顺序与必要验证

1. 替换 KeyboardState 的按住模型，建立独立事件/状态模型，完成两轴抵消、组合、调速和去重；更新连续页提示及高亮。
2. 更新连续服务的最新目标调度、通信宽限、清晰停止原因和原始接收时间传递；全局实验检查保持。
3. 更新连续协议 v2、MCU 普通归零平滑和 2000ms 期限，同步假设备与协议说明。
4. 只运行相关必要验证并构建固件；确认通过后再安排实车烧录和验证，软件通过不记作实车通过。

必要验证按行为归组，优先修改已有连续控制用例，不增加重复全量测试：

| 验证 | 必须证明的结果 |
|---|---|
| 输入状态 | 九种组合；同向幂等；反向一次抵消/两次反向；松键保持；同时相反输入确定归零；WASD 独立且限幅后可直接减小 |
| Qt 与生命周期 | 实际按键到服务、页面状态显示、STOP/失焦/切页清状态，重新使能不恢复运动 |
| 生产 Host/C 桥 | 普通回正/减速每 10ms 符合变化率限制，停止前不清 PI；STOP 立即清；倒车方向与参数冻结正确 |
| 抖动与故障 | 300～500ms ACK 延迟可恢复；600ms 未确认停止；300～800ms 单路遥测短缺可恢复、1000ms 停；单次丢弃增量不停止；持续积压/硬溢出按各自规则处理 |
| 期限与兼容 | Host 停止发送后 MCU 在最后期限停车；u32 回绕/迟到旧帧不续期；v1 不启用 v2；晚 ACK/链路恢复不重放 |

实车验收先记录现版一次故障的真实触发原因，再对比新版；在相同速度、地面和控制参数下观察速度波动、转弯切换、停止次数以及实际通信延迟。保持现有 PI 参数，避免把通信改动和增益调参混在一次对比里。当前没有测量依据给出速度波动百分比或“断连已修复”的承诺。

## 10. 2026-11-04实施记录

- 默认模式采用离散指令锁存、独立V/W幅值、按键去重与同批相反方向归并；键盘和未来识别器共用`DrivingEvent`入口。来源序号单调去重（最多32来源，不淘汰后重接收旧事件），生成超过1s的事件丢弃。同批幅值事件按次数更新。
- 按用户新增要求保留“按住方向键 · Z/X调速（原操控）”，页面下拉切换；切换先STOP，清空两套方向/物理按键/待处理输入，重新使能从中立开始。新会话默认回到离散模式。原模式Host保持200ms ACK、500ms基础STATE、200ms连续遥测、2Hz、1000ms目标及松键立即归零。
- 默认模式实现单在途和最新目标调度，600ms ACK、两类遥测各1000ms、非溢出积压500ms宽限及期间暂停普通目标。按原始收包时间计龄，重复/倒序tick与遥测seq不刷新。真实事件/回包溢出和传输关闭直接停止；丢弃计数单独告警，设备实际故障仍停止。
