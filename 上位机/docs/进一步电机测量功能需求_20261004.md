# 进一步电机测量功能需求（2026-10-04）

本清单用于后续开发，依据2026-10-04已有开环数据和当前双端源码能力审计。本轮实际进入57次，55次完成、2次中止；54个主测量槽位全部完成，另保留旧阶段的1个额外完成试次与2个中止试次。全部仍使用固定PWM。第二完整时间块跨至新设备会话、相隔约3小时，分时段呈现。真正持续转动时的维持阈值尚未具备测量能力。

用户已要求自主进行测量，并要求列出后续功能需求。实验仍保存真实用户授权、冻结版本、实际能力、执行身份和停止边界。

## 当前缺口与开发顺序

当前 `PROJECT_V1` 一次ARM之后只接受一次固定PWM/轮速SET，执行期间再次SET拒绝；绝对deadline与本地duration取早，总时长最大1000ms。Host Controller也拒绝在运动锁存期间发SET；MCP步骤仅有固定左右PWM、duration、重复与主动STOP。这是现有契约，不能通过上位机定时发送多个SET实现不断电降PWM。

优先完成两项：一是MCU本地执行的有限双段PWM及Host/MCP记录分析，才能测有限窗口维持；二是可定位延迟与丢弃层次的接收时间证据，继续保留真实500ms新鲜STATE门槛。随后补重复时间块管理与阈值边界加密。PI/前馈与温度、电流归因应在对应依赖具备后独立实施。

## P0：真正维持测量必需的能力

### M01　MCU本地有限分段PWM与实际CAPS声明

**目的：** 已启动后在同一次受限运动内降PWM，排除“先停止再起步”与主机无线调度延迟造成的替代实验。

**具体行为：** 新增独立有限profile命令，旧SET和ARM契约保持。最小支持两段左右PWM、首段时长、总时长及绝对deadline；完整profile一次原子提交、校验、接受。显式PWM ARM且inactive时才接受，在MCU100Hz控制任务根据本地tick切段。`end_tick=min(接收tick+total_ms,绝对deadline)`只设置一次，切段、ACK、查询和重复请求均不得续租。当前先维持total≤1000ms，段数/字节/队列有硬上限；同轮维持阶段不得换向，单轮实验另一侧全段0。到期、本地禁止、按键STOP、协议STOP、接收/发送溢出及控制超时取消全部剩余段并清零。

只有真实CAPS明确声明profile能力及段数/时长限制时，Host/MCP才启用。当前CAPS features=0x0F，Host会拒绝未知位；新增feature及能力字段必须双端冻结，保留旧固件兼容。无法确认能力时禁止发送新命令，不能由连接成功或本地主机版本推断实物支持。

**依赖与责任：** 必须修改MCU协议核心/控制任务和Host协议服务/能力解析；需要新的协议契约、实际编译烧录及CAPS回读。上位机独立更新不能让当前实物具备profile；本清单不实施烧录。

**验收：** 黄金向量与非法长度/幅值/时长/段数；ARM前拒绝、active期间新profile/SET/重复ARM拒绝；同seq重放拒绝且不改变截止时间；排队导致截止提前、segment_end≥end_tick时不执行后段；tick回绕、STOP与所有本地停机条件清除段状态。实际C核心与Host字节桥、假设备全部通过后，再确认实物CAPS和输出段切换；软件测试与实物验收分别记录。

### M02　Host/MCP冻结分段实验表与有界执行

**目的：** 让每个启动+维持试次可提前审查、复算，避免MCP任意字节或主机偷偷续租。

**具体行为：** 在实验模型增加明确 `segments` 字段，最小两段；冻结快照列出各段左右PWM/时长、总时长、deadline策略、对照类型、重复及时间块。校验器拒绝字段猜测、非法值、bool当整数、同轮换向和超CAPS。开始仍核对真实CAPS、新鲜STATE、本地允许、失能、记录完整性与RAM回读；一试次只ARM一次、profile一次。Control Owner互斥、MCP独立心跳、500ms状态门槛和STOP取消所有后续步骤保持。

反复试验按完整profile重复，不能拼接独立SET模拟长时运行。自适应改档创建新冻结版本和摘要，旧版本失效；沿用用户已给的本任务测量授权记录，不伪造人工批准或现场观察。

**依赖与责任：** Host可先独立开发模型、预览、假链路执行、工具schema、UI展示和录制；真实执行依赖M01与实际能力。界面通过服务调用，传输只负责字节。

**验收：** 冻结摘要与执行内容一致；旧CAPS/未知能力拒绝且不发运动字节；校验上下界、版本失效与重复启动；活动阶段人工运动操作拒绝，STOP取消剩余段和试次；断线/过期/记录失败不自动重连、重发或恢复。假设备不访问实物，正式测试使用注入链路或 `--no-auto-connect`。

### M03　接受、分段执行与分段记录分开证明

**目的：** 区分“MCU已接受整表”与“实际执行到维持段”，避免ACK成功直接生成维持成功结论。

**具体行为：** profile ACK仅证明接受。执行证据需含profile命令seq、segment_index、计划/实际切换device tick、当前PWM、armed/mode及停止原因，并关联run/trial/session/connection。通过协商后的扩展STATE或专门有界阶段事件回传，具体字节在协议设计时冻结；不得直接改变旧STATE保留0字段的契约。Host同步保存原始字节、接收时间、协议事件、每段样本数和实际观察跨度。段未出现、被deadline截短或观测不足与“维持失败”分别记录。

**依赖与责任：** MCU事件/STATE扩展与Host解码共同完成；Journal、CSV、报告、图和独立离线复算由Host实现。字段同PWM两段也应可区分，不能仅凭PWM值猜段号。

**验收：** 无ACK、拒绝ACK、接受后提前STOP、段切换后延迟接收、丢失切换事件、同seq迟到STATE及同PWM两段的分类正确；原始记录独立重建段边界及统计与摘要一致。回传记录有界，遥测或事件溢出明确诊断并终止实验。

### M04　维持判定、惯性对照与结论期限

**目的：** 区分电机启动、短时惯性延续和较低PWM下的维持，给出可重复的边界区间。

**具体行为：** 最初可采用400ms较高PWM启动+600ms低PWM维持，total1000ms。每侧每方向加入“高PWM继续保持”正对照和“启动后PWM0”输出归零对照，各≥3次；零PWM、失能与驱动模式的物理含义按真实驱动契约记录，不能直接宣称自由滑行或断电。

只有启动段已观测同向转动，维持段实际发生且观察充分时才能判定维持；未启动记“不成立”，段不足记“观测不足”。保留失败0反馈，不仅看单次最佳速度。比较完整时序、维持末段速度/趋势及对照衰减；末4条≥3条同向可作兼容短窗指标，但不能单独排除惯性。粗扫成功/失败相邻边界做25或50PWM加密，多时间块重复，按侧别、方向和历史分别报告区间及成功比例。

**依赖与责任：** 分段能力M01–M03；算法、对照模板和离线图表可由Host独立准备。需要实物驱动归零语义与轮速标定核对。

**验收：** 合成与真实记录覆盖启动失败、维持段零速、短暂惯性后停、真正段内持续反馈、截止前截短和中止。报告明确“600ms有限窗口”，不输出数秒至数分钟的稳态保证。长时维持需另行明确有界更长CAPS、停止机制及实物验证，不能用连续短试次自动续租实现。

## P0/P1：接收延迟与完整性证据

### R01　完整接收时间链与解析诊断（P0）

**目的：** 定位蓝牙、IPC、Qt主线程或半帧计时在哪层造成迟到与丢弃，避免把“已解析CRC正确”写成无丢失。

**具体行为：** 为每RX块记录唯一ID、底层采集monotonic时间及UTC映射、IPC送达/Controller入队/Qt处理时间、字节长度和连接身份。记录半帧候选开始时间、会话/seq/长度等可用身份、累计已收字节、候选年龄及每次追加来源；诊断列出CRC/长度/版本/过期/重同步丢弃计数与字节数，保持有界缓存。保留设备RX/TX累计、录制dropped、解析rejected/discarded和事件丢弃四类指标，不混为一个“完整性正常”。

**依赖与责任：** 多数由Host蓝牙子进程、IPC、worker、Controller、parser及Recorder独立开发；不改传输为设备语义层。底层时间应在实际采集点标记，不能事后用处理时间伪造；设备侧环形缓冲详细时序若要归因需MCU另增计数。

**验收：** 已完成原始分块回放，定位并修复31ms分片继承旧候选起点造成的119ms误算，修复保留真正108ms分片超时；相关178项测试通过。这只是已定位的一处缺陷。进一步注入Qt阻塞、IPC延迟、连续RX候选、半帧未完成、CRC损坏及洪泛，证明能区分采集迟到和处理迟到。诊断有界且不拖慢接收；记录暂停显示仍完整保存。显示恢复与后台接收另测，不能将暂停显示后健康窗口视为修复全部原因。

### R02　新鲜度计算与待处理有效帧顺序回放（P0，定位后决定修复）

**目的：** 核对“新鲜有效帧已到达但仍排队”和过期检查的顺序，保持真实控制状态时效。

**具体行为：** 先用R01时间证据重放，确认新鲜度引用采集、接纳或处理时间的实际语义，以及半帧候选年龄在追加字节/无字节tick/健康检查之间的顺序。根据可复现结果制定修复，不能预先声称计时bug已定位。新鲜度必须反映实际有效STATE的年龄；迟到旧帧不得通过刚处理、刚查询或重复STATE刷新年龄。

**依赖与责任：** Host独立回放与实现审查，必要时MCU tick时钟误差标定。不要求新增profile即可诊断。

**验收：** 真正超过500ms无有效STATE仍中止；有效帧实际迟到后不能恢复已中止运动；同会话重放、乱序、积压集中到达不刷新成假新鲜。对“待处理新帧与timer先执行”给出可复现测试及时间证据。**不放宽500ms门槛、不停用完整性检查、不靠自动重发掩盖延迟。**

### R03　通信健康窗口与停止观测面板（P1）

**目的：** 开始实验前后快速判断真实会话的数据健康，并让记录中的中止原因可解释。

**具体行为：** 显示实际采集年龄/处理延迟分位数与最大值、STATE tick/seq跳变、半帧/CRC计数增量、设备和Host各层丢弃起点/终点。RX累计随重新连接变化时记录新基线与会话，不能延续旧数值。只读健康检查窗口不发送ARM；报告分别显示STOP排队、ACK、首失能/PWM0 STATE、首次零反馈、连续零反馈确认，不能叫机械停止时间。

**依赖与责任：** Host独立实现，R01供给时间字段。物理急停/硬件看门狗属于另行硬件或MCU依赖，本界面不等于独立保护。

**验收：** 新会话基线与中途增量正确；查询往返耗时不被误当Controller状态年龄；后台/显示暂停/恢复情况下停止记录可比，报告不因缺少某层时间字段给出虚假精度。

## P1：重复时间块、加密与中止可复算

### E01　显式时间块与静置任务

**目的：** 阈值随时间变化时保留可比条件，不只输出一个全程平均最低PWM。

**具体行为：** 计划描述时间块、相同锚点、交错/反序/轮转顺序、重复数、静置最小时间和次数预算；记录实际静置起止与首个非零输出时间。图表按方向、侧别、时长、时间块显示分母、失败、观测不足；全程合并作为辅助结果。静置≥60秒不自动命名冷机。

**依赖与责任：** Host/MCP可独立实现；固定PWM已有可执行基础，profile则依赖M01。温度控制或真实冷机判定依赖传感器/额外实验。

**验收：** 假时钟验证静置未满不运动、停止取消静置后所有步骤；实际时间块顺序与冻结表一致；对阈值非单调变化和失败样本保留正确。软件等待仍响应STOP与新消息。

### E02　边界自适应加密与新版本

**目的：** 在有限预算内定位启动/维持边界，同时防止同一阶段悄悄改变PWM。

**具体行为：** 粗扫结果仅生成下一阶段草稿；相邻可靠成功与失败区间按25/50步长加密，多次重复；每次换档表重新preview冻结并存摘要、选择依据和剩余预算。当前样本不足、时间漂移或通信不足时给出区间/未定，不强制输出单点。不得超过预定PWM/时长/试次预算。

**依赖与责任：** Host独立实施，维持加密依赖profile。任务已有授权可在明确测量边界内自主冻结执行，不增设重复许可问题。

**验收：** 同一版本内容不可变；STOP/中止后原剩余槽位取消，新补测使用新版本、run身份和实际时间块标签。全成功或全失败的有界粗扫正确输出单侧界或无法确定，不自动无限升档。

### E03　中止、补测与独立复算

**目的：** 区分计划槽位、实际进入、完成与充分观测，补测不覆盖旧失败。

**具体行为：** 统一索引保存原阶段及恢复阶段；中止保留全部原始字节和实际进入试次，取消槽位单列。补测从新冻结表开始，不重发结果未知命令。自动报告与独立原始CRC/STATE分类/时间分析交叉核对；输出字段包括分段观察跨度及数据缺口。

**依赖与责任：** Host/MCP和离线分析独立实现。旧原始数据不可改写，后补人/助手观察单独保存且标注来源。

**验收：** 一次中止+完整补测可得到“55进入、54完成、1中止”一类真实计数，不能写成只有54实际试次；充分无反馈保留失败0值；中止不计完成成功率，取消不计失败；独立复算与报告不符时阻止成功发布。
