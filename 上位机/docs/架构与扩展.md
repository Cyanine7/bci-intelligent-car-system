# 上位机架构与扩展

日期：2026-10-03。v0.4.0 在 PROJECT_V1 双端协议、参数读写、有限开环实验与轮速 PI 服务上新增连接配置与启动单次自动连接。MCU 工程与根目录记录由固件实施部分维护；本说明覆盖上位机。用户已报告嵌入式接口完成、无线通路可行；本次自动连接实现尚未另行操作实车，软件夹具与编译结果不等于实车验收。

## 数据与控制路径

```text
USB / 虚拟 COM ─ QThread 独占串口 ─┐
Classic SPP ─ QtBluetooth 子进程 ──┼─ 字节事件 ─ 协议适配器 ─ 遥测/日志/记录
模拟设备 ─ QThread 模拟适配器 ─────┘

面板 ─ 参数/功能服务 ─ Controller 语义入口 ─ 协议编码 ─ 统一发送入口
```

传输只处理字节和链路结果。协议负责帧、语义及单位；服务负责功能操作；面板负责展示和用户草稿。只有统一发送入口持有链路发送权限。原始调试发送仅开放给 LEGACY_APP；PROJECT_V1 禁用原始发送。

当前 MCU 的 `LEGACY_APP` 是 `{C左轮幅值:右轮幅值:估算电量}$`，轮速整数除以 100 为 m/s。厂商完整参考固件的 A/B/C 帧定义不同，尤其其 C 是 PID 等参数，不能共用当前 C 帧解析器。没有 CRC、序号、设备时间和 ACK 的旧帧不证明运动方向或命令执行。

## 协议、能力和参数服务

`car_host.device` 的公开边界：

| 接口 | 用途 |
|---|---|
| `register_protocol_adapter(protocol, factory, capabilities=None)` | 启动时注册明确选择的协议；factory 接收 source，重复标识拒绝 |
| `create_protocol_adapter(protocol, source)` | 创建具有 feed/reset/pop_issues 的适配器；未知协议拒绝，不发送探测字节 |
| `capabilities_for_protocol(protocol)` | 取得冻结的 `DeviceCapabilities` 快照 |
| `DeviceCapabilities.supports(name)` / `reason_for(name)` | 查询 telemetry、raw_send、parameter_read、parameter_write、open_loop、motion 等能力与不可用原因 |
| `ParameterService(gateway).read_parameters()` | 先检查 parameter_read，再请求网关的 read_parameters 语义命令 |
| `ParameterService(gateway).apply_parameters(values)` | 先检查 parameter_write 和基本映射形状，再提交 apply_parameters 语义命令 |
| `DeviceResult(success, status, message, request_id=None, values=None)` | 明确表达 unsupported、invalid、queued 等服务结果 |

能力声明与连接状态分开。注册表中的旧协议能力来自本地源码，不是 MCU 发回的 CAPS；它只开放遥测和原始发送。PROJECT_V1 注册快照不启用功能，匹配 HELLO 的真实 CAPS 才更新能力。参数服务每次读取网关当前快照；连接、协议或设备启动变化会重置能力和待确认操作。

服务依赖的网关具有 `capabilities` 与 `send_command(command, values=None)`。未来适配器可实现 `encode_command(command, values)`，由能力通过的 Controller 语义入口调用；参数读取/修改默认分别要求 parameter_read/parameter_write。新增语义命令还应在适配器的 `command_capabilities` 字典中声明所需能力，例如将自定义开环语义映射到 open_loop；没有能力映射的命令会拒绝。当前旧适配器没有该编码器，不能调用猜测的参数、开环或运动协议。`success=True, status='queued'` 仅表示进入发送路径，不表示 MCU ACK 接受或参数生效。

`project_protocol.py` 按 [冻结协议](../../bci-intelligent-control/docs/PROJECT_V1协议.md) 编码 CRC16、有界载荷、session 与 seq，解析 48 字节 STATE（末尾 reserved=0）、CAPS、ACK、PARAMS。连接后随机非零 session HELLO，真实 CAPS 才更新能力。Controller 保存最多 32 个未确认请求与 128 个结果，2 秒无回包标为 unknown，不重发；STOP 在请求槽满时淘汰最旧参数请求为 unknown 以保留停止入口，同一个待确认 STOP 不重复发送。

`MotionService` 提供 arm_pwm / arm_speed / set_pwm / set_speed / stop。Controller 以最新 500 ms 内 STATE、CAPS 上限、模式和前次指令覆盖情况校验有限控制，并用 tick + 接收后时间 + duration 生成 deadline。每次实验只允许一个 SET，禁止活动期间续租；运动到期后必须重新 ARM。参数须已失能，四项 q100 原子提交到 RAM；PARAMS 只接受当前 session 和匹配 GET / SET 请求的身份。独立实际值与草稿见 [使用说明](PROJECT_V1使用.md)。

## 独立功能面板

`car_host.tools` 提供 `ToolSpec(id, label, required_capabilities=(), factory=None)`、`ToolRegistry` 与 `create_default_tool_registry()`。`ToolSpec` 的 tool_id/title 是 id/label 的只读别名。

- `registry.register(spec)` 注册独立功能，重复 ID 拒绝；`tools()` 返回按注册顺序排列的定义，`get(id)` 查询定义。
- `availability(id, capabilities)` 返回 enabled/reason。缺少设备能力或没有面板工厂都会禁用，连接成功不能绕过它。
- `create_panel(id, gateway)` 先检查能力，再调用 factory(gateway)；不可用时抛出包含原因的 RuntimeError，不创建面板。
- 默认 open_loop、pid、motion 已注册 `project_panels.py` 中的独立面板；LEGACY 能力不足时仍禁用。PI 参数面板需要 parameter_read 与 parameter_write；PWM / 轮速面板需要相应能力并按新鲜 STATE 控制操作按钮。

新增功能时注册面板工厂并注入界面的工具注册表。工厂可以创建 QWidget 或 QDialog；面板通过网关和服务访问设备，不导入蓝牙子进程或直接调用串口。无需全局插件扫描、微服务或空实现目录。

## 连接配置与启动单次尝试

`preferences.py` 的 `BluetoothProfile` 保存本地别名、MAC、RFCOMM 通道、协议和显示名称；`AppPreferences` 另保存启动自动连接开关。默认蓝牙 SPP / PROJECT_V1、用户确认的 MAC `2A:A2:19:07:1B:8B`、名称 `WHEELTEC`、别名“我的小车”和通道 1。只有 MAC 决定连接目标，名称与别名用于显示；别名不发送给模块。默认通道来自历史配置，本次没有重新核实。扫描列表可按名称或 MAC 筛选，选择模拟自动使用 LEGACY_APP，返回真实设备恢复此前协议。

正式入口 `__main__.py` 通过 `PreferencesStore` 加载项目目录的 `config/preferences.json`，使用 `schema_version=1` 的显式字段结构。文件上限 64 KiB，加载校验字段、类型、MAC、通道、协议和显示文字；保存使用同目录临时文件与原子替换。文件不存在时使用默认配置并尝试写入；损坏、版本不支持或读取失败时保留警告，使用默认显示配置并禁止本次自动连接，供检查与手动恢复。“保存设备配置”只写连接配置与开关，不保存会话、ARM、运动目标或 PI 参数，也不发起连接。

`startup.py` 的 `StartupAutoConnector` 是独立小型 QObject，仅由正式入口安装。窗口显示后使用单次 500 ms QTimer，按当前配置最多调用一次 Controller 的连接入口；配置编辑、扫描、手动连接 / 断开及退出会消耗并取消尚未执行的尝试。连接失败和后续掉线都不会安排重试。`--no-auto-connect` 只禁用本次启动，不改保存文件。`MainWindow` 自身不启动连接定时器，直接构造窗口的测试和界面验收不会自动访问蓝牙硬件。

自动连接只建立字节链路并遵循现有 HELLO 流程：停止并创建新会话，不自动 ARM、运动或恢复参数。真实 CAPS、新鲜 STATE 和每次操作校验继续由 Controller / 服务负责，启动层不能绕过这些门控。

## Classic SPP 子进程与有界生命周期

只支持 Classic RFCOMM/SPP，首次配对由 Windows 设置处理；可按保存 MAC 直连、扫描或手填 MAC。默认服务通道 1、可选 1–30；通道不是 COM 号或波特率。MCU—模块 UART 配置与无线服务不同，当前主工程 UART 为 230400/8N1。用户已确认实物为 WHEELTEC、MAC `2A:A2:19:07:1B:8B`；实际通道与模块 UART 仍须按实物核对，JDY-33 仍是未核实的候选型号。

独立 Python 子进程运行 QCoreApplication/QtBluetooth。父端以 QProcess 异步 stdin/stdout 和 GUI QTimer 监督，不使用 waitFor* 同步等待。隔离针对已见 Windows Qt 写入等待和同步 bytesWritten 回调；不宣称已证明所有底层写入无限等待。

扫描与连接期限各 10 秒，TX 3 秒，停止宽限 2 秒。发送前登记请求，只派发一个在途请求；超时后结果未知、不重发，并清除旧队列。停止先拒绝新请求，再关闭链路；必要时父端终止子进程。终结状态单独锁存，进程退出后清理管道，排空事件并收尾录制。关窗异步等待清理，不在 UI 线程长时间 wait。

待发送128条、单次4096字节、通信事件1024条、扫描设备128个；IPC 单包、解析缓存及待写缓冲另有限额。事件携带 connection_id，发送另有 request_id，旧连接/重复终结/迟到结果不会影响新连接。数据丢失应保留诊断、重置半帧，并把活动录制标为不完整。

## 记录与验证

遥测 CSV 保留 source、协议、UTC、电脑单调接收时间、原始帧与 connection_id；PROJECT_V1 另记录设备 session、last_seq、tick、signed speed、PWM / encoder、停止原因与 revision。通信日志保存原始字节与连接身份，QUEUED/TX/ERROR 中记录 request_id。Controller 将每个协议 seq 映射至发送 request_id；STATE 不强行归属于某一个发送请求，缺失字段不伪装成零。

屏幕日志1000条、绘图60秒/最多6000点、录制队列2048条。暂停或清空显示不停止接收与录制；录制失败和溢出会锁存不完整状态，停止后收尾文件。蓝牙终止只表示本机链路关闭，不能替代 MCU 本地租约和停机反馈。

扩展验证先使用注册的测试协议、假网关、假面板和故障子进程：旧协议参数请求不发送字节，注册新协议不更改传输，能力换代关闭功能，服务不误把 queued 当作生效，IPC 分片/洪泛/挂起/迟到结果/退出均能清理。连接配置与启动尝试可注入假 Controller 验证保存、校验、取消和单次调用；这些测试不操作真实设备。用户确认的无线通路和 MAC 与本次新增启动实现的验收分别记录；自动连接、通道、模块 UART、固件格式、实车运动与停车仍需相应硬件检查。
