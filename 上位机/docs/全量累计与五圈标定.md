# 全量累计与五圈标定

2026年10月8日。本次已准备MCU全量累计、上位机五圈计数面板及录制校核。

**MCU每个100Hz控制周期累加全部编码器读数，蓝牙每50ms回传累计快照。你只需开始记录、依次转两轮各五圈、结束记录；上位机用累计终点减起点计算每圈计数。**

## 已准备的内容

- 64位有符号累计，左、右分开；失能期间也记录手动转动。
- 显式能力查询及ACK确认，旧固件不会假装已支持累计。
- “全量编码器 · 五圈计数”面板，开始/结束marker与encoder_totals.csv异步有界保存。
- 手动计数期间拒绝ARM、运动及其他参数命令；STOP仍可用并取消基线。
- 断线/会话/epoch变化、状态过期、期间新增迟到采样或记录丢失时不发布有效标定。
- 结束前累计值至少200ms未变化且轮速0。
- 差速轮径已改66mm、轮心距160mm；CAPS回读当前固件实际换算参数。

当前每圈1560只是13线、四倍频和N30的名义值，等待实物五圈结果。旧85mm数据保持原样，新固件速度按66mm换算，不能再次乘66/85。

## 需要你操作的步骤

1. 保存现有录制，断开上位机蓝牙，使无线烧录工具独占连接。
2. 用已有无线烧录流程选择本次新文件 **bci-intelligent-control/WHEELTEC.bin**。本次文件29212字节，SHA256：
   `751d14e8eac42ec9274c66d4869fc64c1415d9bcc9f1ed1e82228a528759ee27`。
3. 固件启动后，退出旧上位机并重新打开“启动自动化调试.bat”，使用PROJECT_V1连接。该入口禁启动自动连接，按保存MAC/通道连接一次。
4. 打开“全量编码器 · 五圈计数”，点击“查询全量计数能力”。应显示100Hz累计、20Hz快照、轮径66mm、轮心距160mm。
5. 两轮停稳、失能/PWM0时点击“开始五圈记录”，等界面提示起点已记录。
6. 与上次相同：先手动左轮完整转5圈，再手动右轮完整转5圈。实际圈数填写5/5。
7. 两轮停稳后点击“结束并计算”。按钮等待累计值稳定200ms后启用；界面给出两轮计数/圈和记录目录。
8. 告诉我记录已完成，我从新目录核对原始快照、基线/终点和计算结果。

这条流程只查询和录制，不发送ARM或PWM。若你已开始普通录制，面板复用它；若面板自动开始录制，结束时保存自己的录制。关闭面板取消正在进行的手动计数。

## 校核与结果

encoder_totals.csv保存每个快照的原始帧、会话、seq、采样tick、全量左右计数及采样诊断。receive_trace.jsonl保存encoder_calibration_start/end，包括真实圈数填写和两个边界快照。

离线校核：

```powershell
cd 上位机
.\.venv\Scripts\python.exe scripts\verify_encoder_recording.py <本次记录目录>
```

生成encoder_verification.json，独立检查原始CRC/CSV覆盖、边界原始字段和模64位差值/圈数运算。它不会连接设备。
