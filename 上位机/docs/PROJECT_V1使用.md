# PROJECT_V1 新固件上位机使用

2026-10-03。上位机 v0.4.0 使用冻结的 [双端协议](../../bci-intelligent-control/docs/PROJECT_V1协议.md)，新增默认无线连接与保存 MAC 后的启动单次尝试。用户已确认嵌入式接口完成、蓝牙通路可行；本次启动自动连接尚未另行连接实车验证，实车运动、轮向、PI 稳定性和停车须分别验收。

## 连接与身份

1. 默认选择直接蓝牙 SPP，并在窗口显示约 500 ms 后按保存配置尝试连接一次。初始设备为用户确认的 `WHEELTEC`、MAC `2A:A2:19:07:1B:8B`，本地别名“我的小车”。连接以 MAC 为依据，名称与别名只显示，不必修改模块名称。需要检查配置而保持未连接时，用 `.venv/Scripts/python.exe -m car_host --no-auto-connect` 启动；该选项不修改已保存配置。
2. 默认应用协议为 **PROJECT_V1 · 新固件 / 有限实验**。RFCOMM 通道默认 `1`、可编辑为 `1–30`；`1` 仅沿用历史配置，本次未重新核实。也可手动改用 USB / 蓝牙虚拟 COM，选择 USART2 对应的 230400 / 8N1；直接 RFCOMM 没有电脑端 UART 波特率设置。
3. 连接成功后自动发送一次随机非零 session 的 HELLO。HELLO 清除旧目标并停止；它不会使能运动。只有身份匹配、CRC 与长度正确的 CAPS 回包才能启用功能入口。
4. 检查握手状态和 STATE。新固件显示有符号轮速、编码器、PWM、设备 tick、电压、停止原因、参数 revision 和 MCU RX/TX 丢失累计。正负号沿用框架；实车极性须核对。

连接配置行中的“启动时自动连接一次”控制后续启动行为，点击“保存设备配置”才保存本地别名、MAC、通道、协议、显示名称和该开关。配置文件为 `上位机/config/preferences.json`，只保存连接配置，不保存参数或运动状态。保存本身不会连接；修改连接字段、扫描、手动连接或断开会取消本次尚未执行的启动尝试。失败或掉线后请查看日志并手动连接，没有后台重试。配置无效或无法读取时显示警告、关闭本次自动连接，检查后手动恢复或重新保存。

LEGACY_APP 保留给旧文本固件与模拟设备。选择模拟设备会自动切换为 LEGACY_APP，切回真实设备时恢复此前协议；模拟设备仍仅提供 LEGACY_APP 约 20 Hz 幅值遥测。没有自动探测协议、自动重连、参数恢复或运动重发。PROJECT_V1 禁用全部原始文本 / HEX 发送，避免裸 reset、AT 与运动指令混用；启动连接不会自动 ARM，参数、开环和轮速操作仍必须满足实际 CAPS 与新鲜 STATE 的门控。

## 有限 PWM 实验

打开“开环实验”面板，先检查本地允许且已失能，点击“显式使能 PWM”，等待新 STATE 显示已使能、模式 1，再填左右轮软件 PWM 与 1..1000 ms 内的时长，点击“执行一次”。输入上限同时受 CAPS 限制（本固件 PWM ±6000）。默认目标为零、时长 200 ms，不会自动发送。

“显式使能”按钮不可点击时，面板会显示具体禁用原因。“本地禁止”对应 MCU 回传的 EN（PD3）输入，不是 PI 参数问题。保持车轮架空，检查板卡独立的电机使能开关，并观察 STATE 是否变为“本地允许”；实物开关位置以对应板卡资料为准。切换硬件开关不会自动 ARM 或运动，仍需用户点击使能和执行。已失能、模式0、启动/会话重建是连接后的正常状态。

每次实验只有一次 SET_PWM，没有循环、心跳续租或自动重复。执行中拒绝新实验和重新 ARM；到期失能，下一次须重新显式使能。STOP 可随时请求停止并失能，等待 STATE 核对停止状态。零 PWM 表示框架软件输出归零，不能当作驱动断电或车轮已实际静止的证明。

控制必须有 500 ms 内、当前会话且已覆盖前次控制指令的 STATE。上位机用最新设备 tick + 接收后的经过时间 + 用户时长生成绝对 deadline；MCU 将其与接收后的本地 duration 比较并取较早者。排队或延迟会缩短 / 拒绝实验。该估算尚未完成时钟误差标定，仅用于受限台架调试。

## PI 参数与有限轮速

“PID / PI调参”面板实际实现左右轮 **100 Hz 增量 PI**，共四项：kp_left_q100、ki_left_q100、kp_right_q100、ki_right_q100。界面输入整数 q100，范围 0..2000000，实际系数为整数 / 100。公式为 `u += kp*(error-error_previous)+ki*error`，error 单位 m/s；Ki 是每个 10 ms 采样的系数，没有 Kd，不等同于按秒归一化 Ki。

先 STOP 并等待新鲜 STATE 确认失能，再读取实际 RAM。面板将实际值、revision、草稿和回读状态分开展示；读取不会覆盖草稿，点击“实际值复制到草稿”才复制。应用一次原子提交全部四项，等待匹配 SET_PARAMS 的 ACK 与 PARAMS 回读，实际值只由身份有效的回包更新。参数只存 RAM、不写 Flash；重启默认四项为零。

“运动控制”使用有限左右轮轮速目标（mm/s），上限同时受 CAPS 限制，本固件每轮 ±300 mm/s。先为两轮各配置至少一个非零 PI 系数，再显式使能 PI 并等待模式 2 STATE，随后执行一次。时长、时效、到期失能、STOP 与不重复规则与 PWM 实验相同。当前实现没有 v/omega、轨迹、脑控自动发送或模型自动整定。

## 请求结果与记录

QUEUED / 写出完成表示本机发送进度；accepted 表示匹配 session、seq、command_type 的 MCU ACK 接受，运动和停车仍以 STATE 为准。协议请求等待 2 秒，超时或断开后标为“结果未知，不会重发”；匹配旧连接或超时请求的迟到 ACK/PARAMS 被忽略。需重新读取实际参数后再由用户决定下一次修改。

遥测 CSV 新增设备 session、last_seq、tick、signed speed、encoder、PWM、电压、mode、armed、local_enable、stop_reason、RX/TX 丢失和 param_revision。暂停图形 / 日志不停止采集或录制；MCU 或电脑缓存丢失均记录诊断，有活动录制时标记不完整。

无线烧录使用已有课程烧录工具。先停止实验并核对 STATE，断开上位机让烧录工具独占蓝牙连接；本上位机不发送裸 reset 或执行烧录。重连后必须新 HELLO、新 STATE、重新读取参数和用户显式使能。
