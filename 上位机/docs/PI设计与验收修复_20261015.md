# PI设计与验收修复

本文件记录上一版实现，其中将Mp/ts作为上限的理解已由用户纠正。当前行为、公式及重复超调问题见[理论设计与重复超调修复](理论设计与重复超调修复_20261015.md)，以下保留作历史记录。

本轮完成上位机和固件修复、离线验证及BIN构建。未连接、扫描、运动或烧录实车。

## 使用流程

1. 重启上位机加载本轮源码。进入“速度环实验”，默认模型已是2026-10-15满电12.6V空载结果；历史非满电空载可另选，负载数据不变。
2. 在“PI参数”自由填写Mp上限、2%调节时间上限及计算阶跃幅值，点击“计算并填入PI草稿”。也可直接输入连续Kp/Ki。算法统一为固定增量PI。
3. 根据实际两段目标检查离散预测的超调、ts、PWM峰值和限幅。预测与实际执行输入分别显示；默认零输入不会因计算或预测而运动。
4. 实车使用前需烧录下述新BIN；连接后显式查询实际速度实验CAPS。应用并回读参数，显式使能，再提交两段一次。旧固件未启用闭环时仍会禁用执行。
5. 等待到期停车及后窗采样，刷新概要、读取完整记录。“曲线与指标”显示冻结目标、计数窗区间及逐轮验收，CSV/JSON保存原始100Hz样本、配置、模型和设计依据。

## 完成的修改

- 默认空载改为左K=7.646220324939004e-5、右K=7.598223770509158e-5，左右τ=0.059s，来源和12.6V参考电压随模型保存。旧非满电模型及原负载模型保留。
- 主计算采用完整PI零点、ZOH、前一控制周期平均速度反馈和10ms增量积分，保留三阶离散特征方程。原仅分母匹配函数改名为pole_match_pi，仅用于显式历史比较。
- 数值设计以不超过自由填写的Mp/ts为目标，并在返回草稿前复核当前幅值下的整数PWM及限幅响应。需要时采用超调更小的保守候选；仍不满足时返回具体错误。连续理论与离散实现分别显示超调/ts，离散设计对象是周期平均反馈。模型预测不包含编码器整数计数量化、死区及负载变化。
- UI、模型校验、软件预测和假设备统一固定PI，拒绝algorithm≠2，36字节binary64协议保持。
- 原始10ms超调与ts统一目标基准；另保留平台超调。每次执行冻结当时的验收目标，之后改界面不改变已执行记录。
- 新计数窗分析给出平均速度、单计数量化区间和调节时间上下界，并计入初始平台量化。逐项和逐轮给出达标、不达标、无法判定。窗口不足、观察不足或区间跨过目标时不会报达标；无阶跃轮不参与。
- 计数窗会平滑瞬时峰值，因此通过结论标为“计数窗估计口径”。原始数据、原始速度超调及其分辨率限制同时保留。小幅阶跃可能仍无法确定是否达到很短的ts，这是记录分辨率的结果。
- 曲线增加左右计数窗估计和ts区间辅助线；指标置于顶部，曲线页面可滚动，1000×720与1320×900均可使用。
- 固件启用SPEED_CONTROL_IMPLEMENTED=1，保留用户实际dt、double小数回存、向零截断、零目标复位、故障与限幅实现。恢复旧mode1直接PWM和profile切段；旧PI仅由mode2处理，mode3/4由实验层处理。
